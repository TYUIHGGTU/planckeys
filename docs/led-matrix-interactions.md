# Planckeys 左板点阵交互设计（数字 / 符号 / 表情 / 小游戏）

> 目标：在现有「平台色 + 状态动态」的基础上，把左板 22 颗轴灯当成一块**低分辨率点阵屏**，
> 用数字表示任务序号、用符号/表情表示状态、用小游戏（贪吃蛇）表示「进行中」，让多平台
> 多任务一眼可辨、且更有趣。

> **落地状态（2026-07）**：核心已实现于 `tools/codex-bridge`——
> 点阵字模（`glyphs.ts`）、贪吃蛇（`snake.ts`）、任务序号（session 维度）、`?`/`!` 快闪、
> 完成任务数字高亮 5s、c3 侧条、working 灯效开关（`--working snake|breathe`）、
> 3 分钟自动熄灭（`CODEX_BRIDGE_IDLE_OFF_MS`）。§7 Codex Micro 借鉴暂未做。

---

## 1. 显示面：4×6 竖向点阵

轴灯物理布局（来自 `tools/led-web/app.js` 的 `AXIS_LAYOUT`，正面顺时针旋转后为 4 列 × 6 行）：

```text
列:  c0  c1  c2  c3
r0:  10  21  22   6
r1:  11  20  23   7
r2:  12  19  24   8
r3:  13  18  25   9
r4:  14  17  26   ·      (c3 缺)
r5:  15  16  27   ·      (c3 缺)
```

- **总计 22 颗**（右下角 r4c3 / r5c3 无灯）。
- **主字区**：`c0..c2 × r0..r4` = **3×5**，正好容纳一个 3×5 字模（已有数字字模）。
- **右侧列 c3**：`6,7,8,9` 四颗——做**平台色侧条 / 进度条 / 心跳**，让单色字形旁边始终有平台色。
- **底行 r5**：`15,16,27` 三颗——做**状态点 / 呼吸底 / 小图标**。

> 结论：一次能清晰显示**一个 3×5 字形**（数字或符号），并用 c3 + r5 共 7 颗做**辅助信息**
> （平台色、进度、注意态）。小游戏则可用满 4×6 全场。

## 2. 字模系统（glyph）

沿用 `app.js` 的 3×5 位图约定（`'1'` 亮），扩展字符集：

### 2.1 数字 0–9

已有（`DIGIT_3X5`）。用于**任务序号**。

### 2.2 符号

| 符号      | 语义                  | 3×5 位图（示意）                            |
| --------- | --------------------- | ------------------------------------------- |
| `?`       | 需要输入/审批         | `111 / 001 / 011 / 000 / 010`               |
| `!`       | 出错/注意             | `010 / 010 / 010 / 000 / 010`               |
| `✓`       | 完成                  | `000 / 001 / 010 / 101 / 000`（对勾变体）   |
| `…`       | 排队/等待调度         | `000 / 000 / 000 / 000 / 101`（可做流水点） |
| `∞` / `>` | 长任务/运行中静态兜底 | 自定义                                      |

### 2.3 「表情」

3×5 分辨率画不了真 emoji，但可做**极简表情图标**（更像像素图标）：

- 笑脸 `smile`：`101 / 101 / 000 / 101 / 010`
- 哭脸 `sad`：`101 / 101 / 000 / 010 / 101`
- 心跳 `heart`：`101 / 111 / 111 / 010 / 000`
- 火 `fire`（长时间跑）：动态两帧交替

> 建议把 emoji 定位成**状态图标语义**（完成=笑脸、出错=哭脸/`!`、心跳=进行中），
> 而不是任意 emoji 输入。真 emoji 在 15 像素下不可辨。

字模统一放在 bridge 侧一个 `glyphs.ts`（与 led-web 的字模保持同源，可从 led-web 抽取共享）。

## 3. 任务序号：每平台按顺序编号，1–9 循环

需求：不同平台的不同任务，按**任务发生顺序**显示不同数字；超过 9 时 `1..9` 循环。

设计：

- 每个平台维护一个自增计数器 `seq[platform]`，每当该平台**新开一轮任务**（一次
  `working` 的起始，或一个新 `session/conversation`）时 `seq++`。
- 显示数字 = `((seq - 1) % 9) + 1`，即 `1..9` 循环（跳过 0，0 留给「无编号/空闲」）。
- 数字**颜色 = 平台色**，这样「数字形状=第几个任务，颜色=哪个平台」两个维度叠加。
- 多平台并存时整板一次显示一个（沿用 §1 的整板单显 + 优先级仲裁）；被抢占的平台在
  **c3 侧条**用平台色点一格作为「后台还有它在跑」的提示（可选增强）。

> 决策点：序号按「session 维度」还是「turn 维度」递增？建议 **session 维度**
> （一个对话=一个稳定编号），turn 内状态变化只改动态不改数字，更稳定可读。

## 4. 状态 → 显示映射（整合版）

| 状态               | 主字区（3×5）                                   | c3 侧条 / r5 底行 | 动态                                 |
| ------------------ | ----------------------------------------------- | ----------------- | ------------------------------------ |
| idle / 空          | 熄灭                                            | 熄灭              | —                                    |
| **working**        | **贪吃蛇小游戏**（见 §5）；或退化为「任务数字」 | c3 平台色心跳     | 蛇自动巡游 / 数字平台色软呼吸        |
| **requiresInput**  | `?`                                             | r5 平台色常亮     | `?` **快闪**（琥珀），提示抬头       |
| **completeUnread** | 任务数字 或 `✓`/笑脸                            | c3 平台色满格     | 平台色**高亮 5s** → soft-unread 极暗 |
| **error**          | `!`（或哭脸）                                   | r5 红/黄          | **黄快闪**                           |

要点：

- 「需要输入时 `?` 闪烁」= 你的原始诉求，直接落在主字区 + 琥珀快闪。
- 「进行中贪吃蛇」= 主字区跑蛇；若想同时看到任务号，可在 c3 用数字的极小提示，或
  蛇吃到食物时短暂闪一下任务号（彩蛋式）。

## 5. 「进行中 = 贪吃蛇」交互

把 working 做成一条在 4×6 场上自动巡游的贪吃蛇，作为「正在思考/执行」的动感指示：

- **画布**：整块 4×6（含 c3、r5，忽略两个缺灯格，蛇路径绕开）。
- **蛇身**：平台色；**蛇头**稍亮；**食物**：琥珀/白点。
- **节奏**：蛇每 `tick`（如 120–200ms）走一格；host 侧渲染，走 0xA2 逐像素帧。
- **与进度挂钩（可选但推荐）**：
  - 每收到一次 `PreToolUse/PostToolUse`（有实际进展）就「喂」一次，蛇**长一节**，
    直观表现「干了多少活」。
  - 蛇长到接近铺满 → 说明这轮工具调用很多（长任务）。
  - `Stop`（完成）→ 蛇「吃满/庆祝」两帧 → 切完成态（数字/✓ 高亮 5s）。
- **AI 巡游**：无真实玩家，用简单寻路（朝食物走 + 撞墙/撞身转向）即可，纯观赏。
- **性能**：4×6 每帧 ≤ 24 像素，0xA2 每包 9 像素 → 3 包/帧，8fps 蛇约 24 包/s，可接受。

> 退化策略：若觉得贪吃蛇太花，working 也可只显示「任务数字 + 平台色软呼吸」，把贪吃蛇作为
> 可开关的 `funMode`。

## 6. 建议的显示优先级与整板仲裁

沿用当前整板单显（一次一个平台），仲裁优先级：

```
error (!) > requiresInput (?) > working (蛇/数字) > completeUnread (数字/✓)
```

- 同级按最近更新时间取最新平台。
- 被抢占平台可选在 c3 点一格平台色，表示「后台仍有它」。
- 全空闲 → 整板熄灭（可加 §7 的「N 分钟后熄灭 + 活动唤醒」）。

## 8. 分阶段落地建议

1. **阶段一（字模基建）**：抽出共享 `glyphs.ts`（数字 + `? ! ✓`），bridge 渲染从「整板纯色」
   升级为「整板纯色 或 主字区字形 + c3/r5 辅助」，先把 `requiresInput=?闪`、`error=!闪`、
   `complete=数字/✓` 做出来。风险低，立刻更好辨认。
2. **阶段二（任务序号）**：加 `seq[platform]` 计数与 `1..9` 循环，working/complete 显示任务号。
3. **阶段三（贪吃蛇）**：working 上贪吃蛇 `funMode`，与 `PreToolUse/PostToolUse` 进度联动。
4. **阶段四（Micro 借鉴）**：`idleOffAfterMs` 自动熄灭 + 唤醒；push-to-talk 流光（若接语音）；
   跟随策略（最近/优先/指定平台）。
5. **阶段五（按键回传，选做）**：若固件支持上报按键，做单击切对话 / 双击前置。
